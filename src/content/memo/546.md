![흩어진 호출 지점이 모두 lookup 하나를 거쳐 배열 참조로 캐시를 찾는다. 같은 참조면 인덱스를 재사용하고, refetch 로 새 참조가 오면 한 번 다시 빌드하며 옛 entry 는 GC 된다. push 처럼 제자리에서 바꾸면 참조가 같아 옛 인덱스가 나온다. 매번 새 배열을 넘기면 항상 miss 다.](/svg/weakmap_ref_cache.svg)

```haskell
-- 같은 배열을 이름으로 반복 조회해 O(n) 스캔이 계속 도는데, 배열이 언제 바뀌는지 추적하기 싫을 때
-- 캐시 키를 배열의 내용이 아니라 참조로 둔다 — 무효화를 참조 동등성에 맡긴다
lookup :: Ref [Item] -> Name -> Cache -> (Maybe Id, Cache)
lookup items name cache = case WeakMap.get items cache of
  Just index -> (Map.lookup name index, cache)                 -- 여기부터 O(1)
  Nothing    -> let index = buildIndex (deref items)            -- 새 참조면 자동 miss, 한 번 O(n)
                in  (Map.lookup name index, WeakMap.set items index cache)
-- delete·clear 가 어디에도 없다: 불변 업데이트면 "데이터가 바뀜" = "참조가 바뀜"
-- 키가 weak 이라 옛 items 가 안 잡히면 entry 도 GC 된다. Map 이면 영구히 붙들려 누수

-- 결과는 참조만 보고 정해진다 — 내용은 보지 않는다
outcome :: SameRef -> SameContent -> Outcome
outcome True  True  = Hit
outcome False False = Rebuild   -- refetch. 옛 인덱스는 옛 배열과 함께 GC
outcome False True  = Miss      -- 매번 [...data]·data.filter() 로 넘긴다 — 무의미
outcome True  False = Wrong     -- push·splice 로 제자리에서 바꿨다 — 느린 게 아니라 틀린 값
-- TanStack Query 의 data·select 결과는 참조가 안정적이라 그대로 넘기면 된다

-- 된 것: 같은 참조로 두 번 불러 buildIndex 가 한 번만 돈다
```
