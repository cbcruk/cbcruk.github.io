![한 턴은 ① task queue 에서 가장 오래된 매크로태스크 1개 실행 → ② microtask checkpoint, 큐가 빌 때까지 전부 드레인(드레인 중 추가된 것도 같은 체크포인트에서 처리) → ③ 필요하면 렌더링 → 다음 턴의 ① 로 돌아간다. 매크로는 드레인 도중 끼어들 수 없어 then·queueMicrotask 는 항상 setTimeout(0) 보다 먼저다. 예: setTimeout(timeout), then(then 안에서 queueMicrotask(nested)), 동기 log(sync) 를 실행하면 순서는 sync → then → nested → timeout 이다 — 스크립트 자체가 첫 매크로이고, then 과 그 안에서 추가된 nested 가 같은 드레인에서 돌고, timeout 은 다음 턴의 매크로다. 중첩이 끝없으면 렌더링과 다음 매크로가 굶는다.](/svg/event_loop_one_turn.svg)

```haskell
-- 이벤트 루프 한 턴: 매크로는 하나, 마이크로는 빌 때까지 전부
turn :: Loop -> Loop
turn = render . drain . runOldest      -- 렌더는 필요할 때만

drain :: Loop -> Loop
drain l = case micro l of
  []     -> l
  m : ms -> drain (run m l { micro = ms })   -- m 이 넣은 마이크로도 이 재귀가 받는다
-- 그래서 then·queueMicrotask 는 항상 setTimeout(0) 보다 먼저다
-- 마이크로가 계속 마이크로를 넣으면 drain 이 안 끝난다 — 렌더와 다음 매크로가 굶는다

-- setTimeout timeout · then (log "then" >> queueMicrotask nested) · log "sync"
order == ["sync", "then", "nested", "timeout"]
--  sync          스크립트 자체가 첫 매크로
--  then, nested  같은 drain
--  timeout       다음 turn 의 runOldest
```
