![명시도가 같으면 뒤에 온 규칙이 이긴다. /b 로 바로 들어오면 head 에 vendor.css(.btn 회색) 다음 shared.css(.btn 파랑)가 와서 파랑이 이긴다. /a 에서 /b 로 이동하면 shared.css 는 /a 가 이미 불러와 앞에 그대로 있고 vendor.css 만 뒤에 붙어 회색이 이긴다. 같은 두 시트인데 순서만 다르다. 순서를 바꾸는 곳은 셋이다. 1 주입: 이미 있는 href 는 건너뛰고 없는 시트만 추가하며 App Router 는 시트를 지우지 않는다. 2 빌드 청킹: 14.2.0 의 새 CSS 청킹(#63157)이 여러 페이지의 CSS 를 한 청크로 병합한다. global CSS 는 병합하지 않게 고친 게 #67373(v15), CSS Modules 의 sideEffects 를 true 로 고정한 문제를 고치는 #70087 은 열려 있다. 3 Pages Router 의 반대 증상: 이동 뒤 서버 렌더 시트(data-n-p)를 지우는데 동적 import CSS 는 이미 있어 건너뛰었으므로 아예 사라진다. #72959 가 동적 CSS 에 data-n-p 를 붙이지 않게 고쳤다.](/svg/next_css_nav_order.svg)

```haskell
-- 명시도가 같으면 뒤에 온 규칙이 이긴다 — 그러니 결과는 <head> 안 시트 순서가 정한다
winner = last . filter (matches el) . headOrder

-- 같은 두 시트인데 들어온 길에 따라 순서가 다르다
headOrder (Direct "/b")        == [vendor, shared]   -- .btn 파랑
headOrder (Navigate "/a" "/b") == [shared, vendor]   -- .btn 회색: shared 는 /a 가 이미 불렀다

-- 순서를 바꾸는 곳 셋
inject sheets head = head ++ filter (`notElem` head) sheets   -- 1 이미 있는 href 는 건너뛴다, App Router 는 지우지 않는다
-- 2 빌드 청킹: 14.2.0 의 새 CSS 청킹(#63157)이 여러 페이지 CSS 를 한 청크로
--   global CSS 병합 수정 #67373 (v15 canary~, 14.2.x 엔 없다) · CSS Modules 순서 #70087 열림
-- 3 Pages Router 는 반대 증상: 이동 뒤 서버 렌더 시트(data-n-p)를 지우는데
--   동적 import CSS 는 이미 있어 건너뛰었으므로 아예 사라진다 → #72959
```
