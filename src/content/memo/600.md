![일을 작은 조각으로 나누고, 조각마다 만드는 쪽이 결과물을 낸다. 만든 과정을 전혀 모르는 평가자가 그 결과물과 기준작(바, 실제로 구해 온 진짜 작품)을 누구 것인지 가린 채 나란히 놓고 어느 쪽이 나은지 하나만 고른다. 기준작이 이기면 가장 큰 차이 하나만 만드는 쪽에 돌려보내 다시 만들게 한다. 끝나는 길은 둘뿐이다 — 평가자가 우리 것을 고르거나, 사용자가 직접 멈추거나. 몇 번 돌았는지는 끝낼 이유가 아니다. 기준작은 Stripe 가격 페이지처럼 이름을 댈 수 있고, 평가자가 실물을 구해 볼 수 있고, 나란히 놓고 하나를 고를 수 있어야 한다. 실물을 못 구하면 평가자가 비교를 지어내 전부 통과시킨다.](/svg/gauntlet_loop_blind_critic.svg)

```haskell
-- 기준작(Bar) = 우리 결과물 옆에 나란히 놓고 겨룰, 실제로 있는 진짜 작품
-- 좋은 결과는 되풀이 횟수가 아니라 기준작이 진짜인지에서 나온다
data Bar = Bar { named, fetchable, comparable :: Bool }

valid :: Bar -> Bool
valid b = named b && fetchable b && comparable b
-- named      이름을 댈 수 있는 특정한 것: "Stripe 가격 페이지" O / "수상작급 SaaS 사이트" X — 막연한 부류엔 실물이 없다
-- fetchable  평가자가 실물을 직접 구한다. 못 구하면 비교를 지어내 전부 통과시킨다 (가장 흔한 실패)
-- comparable 나란히 놓고 하나를 고를 수 있다

data Verdict = Ours | Theirs Gap   -- 우리 것 승 / 기준작 승 + 가장 큰 차이 하나

-- 평가자(critic): 만드는 쪽이 자기 것을 심사하지 않는다. 다른 에이전트라 얼마나 애썼는지 모르고, 누구 것인지 가린 채 본다
-- 가혹하게 — 칭찬은 쓸모없다. 10점 만점 점수는 라운드마다 후해져 정말 나아졌는지 알 수 없으니
-- 둘 중 하나만 고르게 한다. 이겼나 졌나만 남아 물러질 자리가 없다
critic :: Bar -> Output -> Verdict

-- 만드는 쪽(build)이 조각 하나를, 평가자가 우리 것을 고를 때까지 다시 만든다
loop :: Bar -> Piece -> Output
loop bar piece = go (build piece Nothing)
  where
    go out = case critic bar out of
      Ours       -> out                          -- 끝. 라운드 수로는 끝나지 않는다 (사용자가 멈추는 것 말고는)
      Theirs gap -> go (build piece (Just gap))  -- 가장 큰 차이 하나만 들고 다시

gauntlet :: Bar -> Goal -> [Output]
gauntlet bar = map (loop bar) . split  -- 따로 판정할 수 있는 가장 작은 조각마다

-- 일을 맡기는 지시문에는 목표·기준작·이 되풀이만 넣는다 (예산은 사용자가 정했을 때만, 도구는 꼭 필요할 때만)
-- 순서·조각 나누기·횟수는 맡은 쪽이 정한다 — 지시가 하나 늘 때마다 스스로 판단할 자리가 하나 줄고,
-- 시작 전에 쓴 계획보다 일하면서 내리는 판단이 낫다
```
