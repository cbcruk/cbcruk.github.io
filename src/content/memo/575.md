![각각 들고 있으면: loading 과 error 가 따로 켜지고 꺼져 네 칸이 생긴다 — 둘 다 꺼짐은 성공, error 만 켜짐은 에러, loading 만 켜짐은 로딩, 둘 다 켜짐은 있을 수 없는 "로딩 + 에러"인데도 적을 수 있다. 그 칸이 한 프레임이라도 그려지면 화면이 튄다. 트리로 옮기면: 로딩(Suspense) → resolve → 성공(본문), 로딩 → reject → 에러(ErrorBoundary), 성공 → 입력 변경으로 promise 를 던지면 → 로딩. 상태는 셋 중 하나라 넷째 칸을 적을 수가 없다.](/svg/suspense_state_collapse.svg)

```haskell
-- 비동기 데이터를 그리는데 로딩·에러가 늘면서 화면이 튈 때
-- 각각 들고 있으면 2 × 2 = 4 칸: 넷째(로딩이면서 에러)는 있을 수 없는데 적을 수 있다
data Flags a = Flags { loading :: Bool, failed :: Maybe Error, result :: Maybe a }

-- 트리로 옮기면 셋 중 하나: 넷째 칸을 적을 수가 없다
data View a = Loading | Failed Error | Done a

-- Suspense 는 비동기를 동기처럼 보이게 한다: 없으면 promise 를 던지고, 오면 다시 그린다
read :: Resource a -> a

render :: a -> Html                            -- 결과 하나만 받는다. loading·error 를 넘기지 않는다
view :: Resource a -> Html
view r = errorBoundary onError                 -- reject → 가장 가까운 ErrorBoundary
       $ suspense spinner                      -- pending → 가장 가까운 Suspense
       $ render (read r)

-- 확인: 있을 수 없는 조합을 적을 수 있는가. 적을 수 없으면 된 것이다
-- 함정: 스피너가 너무 빨리 떴다 사라지는 건 이 축이 아니다 → 573. stale-while-revalidate → 570
-- 모양은 algebraic effect 의 handler 에서 따왔다 — 다만 되돌아가 이어 실행하지 않고 다시 그린다
```
