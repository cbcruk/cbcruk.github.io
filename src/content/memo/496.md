![Children API 로 children 을 재귀 순회하며 원하는 type 을 찾을 수 있다 — Fragment 는 풀고, 문자열·숫자는 isValidElement 로 거르고, props.children 으로 내려간다. 하지만 어디에 두든 찾아 주는 Tabs 는 암묵적 의존·약한 타입·매 렌더 순회로 예측하기 어렵다. React 문서도 Children 은 드물고 깨지기 쉽다고 한다. 대신 Tabs.Root > Tabs.List > Tabs.Trigger, Tabs.Content 처럼 구조를 소비자가 드러내는 Compound Component 로 쓴다.](/svg/children_traverse_vs_compound.svg)

```haskell
-- Children API 로 트리를 뒤질 수 있다 — 가능하지만 비추천
traverse :: Type -> ReactNode -> [Element]
traverse t = concatMap go . toArray
  where
    go c | not (isValidElement c) = []                         -- string·number 도 들어온다
         | type' c == Fragment    = traverse t (children c)    -- Fragment 는 푼다
         | otherwise              = [c | type' c == t] ++ traverse t (children c)

-- 동적 래핑: 링크가 하나라도 있으면 그대로, 아니면 <ul> 로
wrap cs | any (isJust . url) (filter isValidElement (toArray cs)) = cs
        | otherwise                                               = ul cs

-- 암묵적 의존 · 타입 약함 · 매 렌더 순회 · 예측 불가 → Compound Component 로
tabs = Tabs.Root [ Tabs.List [Tabs.Trigger "a" "A"], Tabs.Content "a" "Content" ]
-- 2013년엔 Context 도 없었다: "선언형"인데 명령형 순회를 주던 이중성
-- deepMap·deepFind·deepFilter 가 필요하면 react-children-utilities
```
