![Year 의 year 는 인자 없이 부르면 number, 문자열을 주면 string 인 오버로드다. T extends R 은 R 처럼 불렀을 때 T 의 시그니처 중 하나라도 받아내는지를 묻는다 — 받아내려면 R 보다 인자를 더 요구하지 않고, 받는 인자 타입이 맞고, 돌려주는 값이 R 의 반환 자리에 들어가야 한다. 그래서 () => number 와 (u: string) => string 은 둘 다 통과하고, (u: number) => number 도 year() 가 u 를 버리고 받아내 통과한다. 반면 ReturnType 과 infer 는 묻지 않고 마지막 시그니처에서 꺼내서, ReturnType 은 string 이고 () => infer R 은 never 다.](/svg/overload_extends_vs_infer.svg)

```haskell
-- T extends R 은 "R 처럼 불러도 T 가 받아내나" — 오버로드면 시그니처 하나만 받아내면 된다
extends :: Overloaded -> Sig -> Bool
t `extends` r = any (`accepts` r) (signatures t)

accepts :: Sig -> Sig -> Bool
sig `accepts` r = arity sig <= arity r              -- 1 더 요구하지 않는다 (남는 인자는 버린다)
               && params r `assignableTo` params sig -- 2 받는 인자 타입이 맞는다
               && ret sig `assignableTo` ret r       -- 3 돌려주는 값이 R 자리에 들어간다

year = [ Sig [] Number, Sig [String] String ]
year `extends` Sig [] Number           == True
year `extends` Sig [String] String     == True
year `extends` Sig [Number] Number     == True    -- year() 가 u 를 버리고 받아낸다

-- infer 는 묻지 않고 꺼낸다: 마지막 시그니처에서. 인자 목록으로 오버로드를 고를 수 없다
returnType year == String                          -- 순서를 바꾸면 Number
(year `extends` Sig [] (Infer r)) == Never         -- r = String 을 꺼낸 뒤 () => String 을 받아내는 시그니처가 없다

-- 직접 정의하면 오버로드 대신 제네릭 하나로
-- year<U extends [] | [string]>(...a: U): U extends [] ? number : string
-- 그러면 ReturnType<typeof y.year<[]>> 로 꺼낸다
```
