![확인 창은 window.confirm 처럼 함수로 불러 답을 받는 게 가장 편하다 — 컴포넌트 state 로 열고 닫으면 쓰는 곳마다 같은 코드가 반복된다. 그래서 react-confirm·react-confirm-alert 는 confirm 을 부르면 별도 DOM 노드에 createRoot 로 확인 창을 렌더하고, 사용자가 고르면 promise 를 그 답으로 resolve 한 뒤 루트를 걷는다. createRoot 에는 셀렉터 문자열이 아니라 DOM 요소를 넘긴다.](/svg/confirm_as_function.svg)

```haskell
-- 확인 창을 window.confirm 처럼 함수로: state 로 열고 닫는 반복을 없앤다
confirm :: Message -> IO Bool
confirm msg = do
  el   <- createElement "div" >>= appendTo body
  root <- createRoot el                          -- DOM 요소를 넘긴다 — '#confirm-root' 같은 셀렉터는 throw
  answer <- newPromise $ \resolve -> render root (confirmDialog msg resolve)
  unmount root >> remove el
  pure answer
-- react-confirm · react-confirm-alert 가 같은 방식
```
