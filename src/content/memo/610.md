![ripgrep 은 질의마다 모든 파일을 열어 읽는다. tgrep 은 미리 만든 trigram 인덱스에서 후보 파일을 마이크로초 단위로 고르고, 후보만 열어 정규식으로 확인한다. 리눅스 커널에서는 후보가 전체 9만 6천 파일의 4~12% 였다. 그래서 파일 하나를 여는 비용이 비싼 Windows 와, 파일이 많은 큰 저장소에서 차이가 가장 크다. 대신 tgrep 은 서버와 클라이언트로 나뉘어 있어 결과 한 줄마다 직렬화하고 프로세스 사이로 보내고 다시 읽어 출력하는 배달비가 든다. 결과가 수만 줄이면 이 배달비가 인덱스로 아낀 것보다 커져 ripgrep 이 이긴다. 페이지 캐시가 따뜻한 리눅스에서는 ripgrep 의 병렬 스캔도 싸서 차이가 작다.](/svg/tgrep_trigram_design.svg)

```haskell
-- 질의 한 번의 비용. ripgrep 은 모든 파일을 열고, tgrep 은 고르는 데 거의 안 쓰고 후보만 연다
cost :: Tool -> Query -> Time
cost Ripgrep q = scanAll files q                                     -- 파일마다 열기·읽기·스캔. 찾은 줄은 스캔 스레드가 stdout 으로 바로
cost Tgrep   q = startup + rtt + lookup q + verify (candidates q) + deliver * matches q
  -- startup + rtt: 질의마다 새 클라이언트 프로세스 + 루프백 TCP 왕복 (벤치에 포함)
  -- lookup: 게시 목록이 파일 번호로 정렬돼 있어 정렬·중복 제거 없이 교집합 — AND 1만 파일 29μs, OR 64항 122μs
  --         마스크 두 바이트(이웃 자리 mod 8 · 다음 바이트 Bloom)가 확인 전에 한 번 더 거른다
  -- candidates: 커널 9.6만 파일에서 4~12% → 여는 파일 수가 한 자릿수 배로 준다
  -- deliver: 결과 한 줄마다 직렬화 → IPC → 역직렬화 → 출력. ripgrep 엔 없는 항
  -- 빠진 항: 인덱스 짓기(Go 3초 · Chromium 248초, macOS) — 한 번 내고 서버가 바뀐 것만 고친다. 벤치는 이걸 빼고 잰다

-- 그래서 차이를 움직이는 것 (행 순서 = 따지는 순서)
margin :: Query -> Repo -> Platform -> Effect
margin q _ _       | matches q `isTensOfThousands` = Flips    -- 배달비가 아낀 것보다 크다
                   | noUsefulTrigram q            = Shrinks  -- MatchAll: 전부 후보
margin _ _ Linux   = Shrinks                                   -- 따뜻한 페이지 캐시 + ripgrep 병렬 스캔이면 무작정 읽기도 싸다
margin _ _ Windows = Grows                                     -- 파일 하나 열기가 비싸 건너뛰는 이득이 어디서나 크다
margin _ r _       | largest r = Grows                         -- 파일이 많을수록 건너뛸 게 많다: Chromium 50만 · gecko 39만은 모든 플랫폼에서 이겼다
                   | otherwise = Shrinks                       -- 가장 작은 Go(1.6만)는 Linux 1.29x
  -- 2026-08-24 측정: 기하 평균 Windows 14.6x · macOS 8.61x · Linux 2.82x. 18칸 중 Kubernetes·Linux 만 0.93x
  -- 커널을 흔한 토큰(read · write)으로 쟀을 땐 후보가 4~12% 로 줄었는데도 0.74~0.95x 로 졌다
  --   → 실제로 쓸 법한 질의로 바꾸자 tgrep 49~128초 → 4.6~8.1초, ripgrep 은 그대로 33~46초 = 배달비만 따로 본 것
  -- 공용 러너 측정이라 같은 줄 안에서만 비교한다. macOS ripgrep 은 같은 질의도 385~550초로 흔들렸다
```
