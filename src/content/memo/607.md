![Freeze 는 바깥부터 Fragment, Suspense, 그 안의 Suspend 와 children 으로 되어 있다. frozen 이 되면 Suspend 가 끝나지 않는 promise 로 Suspense 를 중단시킨다. 그러면 React 는 안쪽을 계속 렌더하지만 DOM 에 커밋하지 않아, 팝오버가 사라지는 동안 내용이 닫기 직전 모습 그대로 멈춘다. 한 번의 커밋 안에서 React 는 자식을 먼저 처리하므로, Suspense 가 바로 아래 요소에 display none 을 붙이고 안쪽의 layout effect 를 정리하고 ref 를 뗀 다음에 Freeze 의 insertion effect 가 돌아 display 를 되돌린다. 숨긴 모습은 한 번도 그려지지 않는다. 되돌릴 요소는 Fragment ref 에 가짜 관찰자를 넣어 미리 모아 둔다. 풀리면 쌓여 있던 최신 렌더가 한 번에 커밋된다.](/svg/react_freeze_exit.svg)

```haskell
-- 닫기와 내용 변경(안내 문구, 고른 항목 맨 위로)이 한 배치로 커밋되면 사라지는 중에 내용이 바뀐다
-- → 퇴장 중엔 커밋을 멈춘다. Suspense 를 빌리고, 딸려 오는 숨김만 걷어낸다
freeze :: Bool -> Tree -> Dom -> Dom
freeze False t _   = commit t                    -- 평소: 렌더한 대로 커밋
freeze True  _ old = unhide (suspend old)        -- 얼림: 렌더는 계속, 커밋은 안 함 → 닫기 직전 모습

-- Suspense 가 중단되면 하는 일 셋 — 앞의 둘은 그대로 쓰고, 셋째만 되돌린다
suspend :: Dom -> Dom
suspend = keepState . skipCommit . hide
  -- {frozen && <Suspend />}: 모듈에 하나 둔 끝나지 않는 promise 를 use → 계속 중단
  -- hide: 바로 아래 요소에 display: none !important, 텍스트는 nodeValue = '', layout effect 정리·ref 떼기

unhide :: Dom -> Dom
unhide = mapElems (\el -> el { display = "" })
  -- 언제: useInsertionEffect. 커밋은 자식 먼저라 Suspense 가 숨긴 직후 같은 커밋 안에서 돈다 → 숨긴 모습이 안 그려진다
  -- 누구를: <Fragment ref> 의 observeUsing 에 가짜 관찰자를 넣어 바로 아래 요소를 Set 으로 모은다
  --         (붙으면 observe · 빠지면 unobserve 가 다시 불린다)
  -- deps 는 [frozen]: React 가 다시 숨기는 건 보임↔숨김이 바뀔 때뿐이다

-- 풀릴 때: 쌓인 최신 렌더가 한 번에 커밋되고, display 는 style prop 의 값(없으면 '')으로 돌아온다
-- 쓰는 쪽: <Popover>{({ isExiting }) => <Freeze frozen={isExiting}>…</Freeze>}</Popover> (React Aria)
--          React 상태로 그리는 hover·press·focus 도 같이 언다. CSS :hover 는 안 언다
-- 버린 길: 닫기 전 상태를 저장 → 다시 그리게 하는 상태를 전부 챙겨야 한다
--          onOpenChangeComplete 로 업데이트를 미룸 → 퇴장이 중간에 끊기면 복잡하다
-- 다만: observeUsing 은 react-dom 19.3 부터다(19.2.0 엔 없다). ref cleanup·use 도 19
--       텍스트 자식은 되돌리지 않아 얼어 있는 동안 비어 보인다
--       퇴장 중엔 ref 가 떨어져 있어 ref 로 재거나 포커스를 다루는 코드는 못 돈다
--       원래 인라인 display 를 지운다 · React 내부 동작에 기댄 트릭이다
```
