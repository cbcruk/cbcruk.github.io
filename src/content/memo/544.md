![보통은 코드를 짠 뒤 테스트를 짠다. SDD(Kiro)는 스펙을 requirements → design → tasks 로 문서화하면서 acceptance criteria 에서 검증 가능한 불변식(testable property)을 먼저 뽑는다 — 명세가 곧 테스트의 원천이다. 그 property 를 순수 함수에서는 fast-check 로 PBT 하고, UI 로 넓히면 Bombadil 이 action generator + property 로 검증한다.](/svg/sdd_spec_to_property.svg)

```haskell
-- 보통: code → tests. SDD: 스펙을 문서화하면서 검증할 불변식을 먼저 뽑는다
data Spec = Spec { requirements :: [Criterion], design :: Design, tasks :: [Task] }   -- Kiro

properties :: Spec -> [Property]
properties = concatMap testable . requirements      -- acceptance criteria → testable property

check :: Target -> Property -> IO Result
check (PureFn f) p = fastCheck (forAll arbitrary (p f))     -- fast-check
check (WebUI app) p = bombadil app actionGenerator p         -- action generator + property
```
