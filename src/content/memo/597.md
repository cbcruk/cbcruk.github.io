![enqueue 는 has → add → queue.add 를 await 없이 한 턴에 끝내 락이 필요 없다. 큐는 무제한 대기열과 동시성 상한이 걸린 실행 중으로 나뉜다. visit 은 GET 으로 본문을 받아 링크를 뽑고 태스크가 끝나기 전에 enqueue 로 돌려보낸다. onIdle 은 대기열과 실행 중이 둘 다 0 일 때 resolve 된다. 자식을 .then·setTimeout 으로 태스크 밖에서 넣으면 부모가 먼저 끝나 onIdle 이 일이 남았는데 resolve 된다.](/svg/node_recursive_crawl.svg)

```haskell
-- start 에서 링크로 닿는 URL 전부 — 처리 결과가 다시 입력이 되어 언제 끝날지 모를 때
crawl :: (Url -> [Url]) -> Url -> Set Url
crawl links start = go Set.empty [start]
  where
    go seen []      = seen                                   -- onIdle: 대기열·실행 중 둘 다 0
    go seen (u : q)
      | u `member` seen = go seen q                          -- seen.has
      | otherwise       = go (insert u seen) (q ++ links u)  -- seen.add 와 자식 추가가 한 걸음: 끼어들 틈이 없다

-- 서로 가리키는 페이지가 있어도 끝나고, 결과 크기가 고유 URL 수와 같으면 된 것이다
```
