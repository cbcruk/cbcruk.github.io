![WebSocket 은 별도 핸드셰이크로 여는 양방향 연결이고, SSE 는 서버가 text/event-stream 으로 계속 내보내는 평범한 HTTP 응답이라 서버에서 클라이언트로 한 방향만 간다. SSE 는 UTF-8 텍스트만 나르고, 끊기면 브라우저가 알아서 다시 연결하며 마지막 이벤트 id 를 기억한다. 이벤트에 이름을 붙일 수 있다. 대신 HTTP/1.1 에서는 브라우저와 도메인마다 연결이 6개로 묶이고, HTTP/2 에서는 기본 100개까지다. WebSocket API 는 역압이 없어 받는 속도를 못 따라가면 메모리에 쌓이고, 열린 연결이 있으면 뒤로 가기 캐시에서 빠질 수 있다. 가장 큰 갈림은 쓰기다: SSE 는 쓰기를 Fetch 로 따로 보내 같은 화면을 고치는 줄이 둘이 되고, 두 줄은 서로 경주해 순서가 깨진다. WebSocket 은 한 줄이라 내 요청과 응답의 순서가 지켜지고, 연결을 한 번만 인증한다.](/svg/websockets_vs_sse_ordering.svg)
