![형식만 애자일: 2주 스프린트 안에서 기능 전체를 한 단위로 기획 → 디자인 → 서버/클라 → QA 가 차례로 넘긴다. 각 직군의 산출물이 다음 직군의 하드 의존성이라, 2주 컨테이너에 워터폴을 압축한 모양이 된다. 수직 슬라이싱: 같은 2주를 얇은 슬라이스 셋으로 잘라, 슬라이스마다 기획·디자인·서버/클라·QA 가 한 바퀴씩 돈다. 단기적으로는 모든 직군에 더 불편하다.](/svg/sprint_waterfall_vs_slice.svg)

```haskell
-- 애자일 의식(스쿼드·2주 스프린트·스탠드업)을 다 갖춰도 워터폴일 수 있다
data Role = Plan | Design | Build | QA

-- 한 단위를 모든 직군이 차례로 넘긴다 — 각 산출물이 다음 직군의 하드 의존성
pass :: Unit -> [(Role, Unit)]
pass u = [(r, u) | r <- [Plan, Design, Build, QA]]

cargoCult = pass feature                     -- 2주 컨테이너에 워터폴을 압축
agile     = concatMap pass (slices feature)  -- 같은 2주, 얇은 슬라이스마다 한 바퀴

-- 갈리는 건 의식이 아니라 단위다 (직군 구성 문제가 아니다)
rituals cargoCult == rituals agile           -- 스탠드업·회고·번다운·Jira 다 있다
-- 형식이 갖춰져 있어 의심이 막힌다 — 처방이 의식 안(스탠드업 개선, 솔직한 회고)으로만 간다
-- 같은 스프린트·같은 기능에서 Discovery(무엇을)와 Delivery(만들기)를 함께 하려 한다

cost agile = (Individual,   ShortTerm, Worse)       -- 모든 직군에 당장은 더 불편
gain agile = (Organization, LongTerm,  Throughput)
```
