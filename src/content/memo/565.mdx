![폰 한 대(Termux) 안에서 순서는 셋이다. ① adb forward 가 Chrome 의 chrome_devtools_remote unix socket 을 localhost:9222 로 연다 — 9222 는 /json 으로 탭 목록을, /devtools/page/\{id\} 로 페이지별 CDP WebSocket 을 준다. ② 파이썬 aiohttp 프록시를 9223 에 띄우고 /json 으로 탭을 고른다. ③ termux-open-url 로 폰 브라우저에서 appspot.com 의 DevTools 프론트엔드를 ?ws=localhost:9223/\{id\} 로 연다. 프론트엔드가 9222 에 직접 붙으면 Origin: appspot.com 이 붙어 Chrome 이 403 으로 거부한다(Origin 검사, Chrome 111~). 프록시는 중계가 아니라 프론트엔드 WS 를 종단하고, 파이썬이 Origin 없는 새 WS 로 9222 에 재접속해 통과한다. ws://localhost 는 localhost 가 secure context 라 HTTPS 페이지에서도 안 막힌다. 다른 길 둘 — Chrome 을 --remote-allow-origins=* 로 띄우거나 프론트엔드를 localhost 에 self-host — 은 해보지 않았다.](/svg/android_devtools_via_proxy.svg)

```haskell
-- 데스크톱 없이 폰 한 대(Termux)로 그 폰의 Chrome 을 디버깅한다 — 내용은 밟는 차례다
-- 막히는 건 하나: CDP WebSocket 핸드셰이크의 Origin 검사 (Chrome 111~)
handshake :: Maybe Origin -> Response
handshake Nothing                                = Upgrade
handshake (Just o) | o `elem` remoteAllowOrigins = Upgrade
handshake (Just _)                               = Forbidden   -- 403
-- Host 헤더 검사(66~, DNS rebinding 방어)는 다른 방어다

-- 프론트엔드가 9222 에 바로 붙으면 브라우저가 Origin 을 붙인다
handshake (Just "https://chrome-devtools-frontend.appspot.com") == Forbidden

-- 프록시는 중계가 아니라 종단: 받은 WS 를 끝내고, Origin 없는 새 WS 로 다시 붙는다
proxy :: TabId -> WS -> IO ()
proxy tab client = connect 9222 tab Nothing >>= pipe client   -- handshake Nothing = Upgrade

debug = do
  adbForward "localabstract:chrome_devtools_remote" 9222   -- /json 탭 목록 · /devtools/page/{id}
  serve 9223 proxy                                          -- aiohttp. /json 으로 탭을 고른다
  termuxOpenUrl (frontend ++ "?ws=localhost:9223/devtools/page/" ++ tab)
```
