![같은 모델이라도 입력이 다르면 무엇을 성공으로 보는지가 갈린다. 구현자는 원본과 자기 추론을 받아 머지되기를 원하고, 리뷰어는 diff 만 받고 이 코드는 틀렸다고 가정하라는 지시를 받아 버그를 찾기를 원한다. 그래서 입력 자체를 잘라야 한다. 64개 병렬은 결과지 원인이 아니다 — 일을 성립시킨 건 컨텍스트 비대칭, 기계적으로 생성되는 큐, 언어를 바꿔도 통하는 합격 판정 기준(테스트 오라클) 셋이다. 판정 기준이 없으면 여기서 멈춘다: Bun 의 Rust 포팅에는 4,174개 파일 6만여 개 expect() 의 TypeScript 테스트가 있었고 스킵·삭제가 0개였다. 없으면 리뷰어를 둘 붙여도 검증되지 않은 코드를 빠르게 생산할 뿐이라, 실패를 열거 가능한 상태(타입 에러 목록·스냅샷·시각 회귀)를 먼저 만든다.](/svg/role_split_why.svg)

```haskell
-- 실패를 기계적으로 열거할 수 있고, 그걸 반복해서 고쳐야 할 때
-- 같은 모델이라도 입력이 성공 기준을 가른다 — 그래서 입력 자체를 자른다
implement :: Original -> Reasoning -> Diff          -- 성공 = 머지된다
review    :: Diff -> Original -> [Failure]          -- 성공 = 버그를 찾는다. 추론은 받지 않는다
-- review 는 "이 코드는 틀렸다" 가정, 최소 3개의 실패 시나리오. 도구는 Read·Grep·Glob 뿐

-- 성립 조건 셋 — 64개 병렬은 결과지 원인이 아니다
feasible = asymmetricContext && mechanicalQueue && isJust oracle
-- oracle 이 없으면 멈춘다: 검증 안 된 코드를 빠르게 낼 뿐 (Bun: 4,174 파일 · expect() 6만여 · 스킵 0)
-- 먼저 실패를 열거 가능한 상태로 — 타입 에러 목록 · 스냅샷 · 시각 회귀

-- 한꺼번에 세우지 않는다
setup = do
  reviewer  <- runFor weeks (agent review) { memory = Project }
  let rules = patterns reviewer                     -- 아래 reject 가 여기서 나온다
  porter    <- agent implement { isolation = Worktree }   -- 변경은 .work/<id>.diff 로
  fixer     <- agent (applyOnly . review)            -- 지적만 반영, 새 기능 금지
  forever (claude "-p" =<< nextFailure)              -- 큐는 세션 밖, 파일로

reject :: Diff -> Bool
reject d = justifiedByComment d || stubbedToCompile d || editsTests d   -- 마지막은 무조건

-- 확인: reviewer 가 tsc·eslint 가 통과시키는 지점을 잡는가 — 린터가 잡을 걸 잡으면 프롬프트가 헐겁다
--   effect 의존성의 의미 변화 · 핸들러 eager/lazy · ?? 와 || · 리렌더 타이밍 · 정리 함수 누락

-- 함정: 비대칭은 저절로 유지되지 않는다
--   부모가 위임 프롬프트에 근거를 요약해 넘긴다 → .work/<id>.diff 경유를 CLAUDE.md 규약으로
--   역할 분리는 프롬프트가 아니라 권한으로 — reviewer tools 에서 Edit·Write 를 뺀다
--   같은 모델 둘은 실패가 상관된다 — 둘째 reviewer 는 model 을 다르게
--   -p 에선 fork mode 가 꺼져 subagent 가 포그라운드로 돈다 — 병렬은 셸에서
--   병목은 모델이 아니라 디스크 IOPS 였다 — 느린 grep 하나가 몇 분씩 얼렸다
```
