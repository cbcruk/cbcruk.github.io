![서버가 날짜를 사용자 시간대로 그리려면 요청에 시간대가 있어야 한다. proxy(Next 16, 예전 middleware)가 쿠키 user-timezone, 없으면 Vercel 의 x-vercel-ip-timezone, 없으면 UTC 를 골라 요청 헤더 x-user-timezone 으로 넘기고, 서버 컴포넌트가 headers() 로 읽어 그 시간대로 렌더한다. 응답 헤더로 넘기면 headers() 가 못 읽는다. 클라이언트는 Intl 로 실제 시간대를 알아내 쿠키에 1년 저장한다. 그래서 첫 방문만 IP 추정값이고 그 뒤로는 정확하며, 서버가 이미 맞게 그려서 깜빡임(FOUT)이 없다. 대안인 useSyncExternalStore 는 서버에서 UTC 로 그린 뒤 클라이언트에서 실제 시간대로 다시 그려 하이드레이션 에러는 없지만 깜빡인다.](/svg/rsc_timezone_cookie.svg)

```haskell
-- RSC 에서 날짜를 사용자 시간대로: 시간대를 요청에 실어 서버에서 그린다
-- (Date 직렬화 · 서버/클라 시간대 불일치 · 하이드레이션 FOUT 을 한 번에)
timezone :: Request -> TimeZone
timezone r = fromMaybe "UTC" (cookie "user-timezone" r <|> header "x-vercel-ip-timezone" r)
                                                    -- request.geo 는 Next 15 에서 제거

proxy r = next r { headers = insert "x-user-timezone" (timezone r) (headers r) }
  -- proxy.js = Next 16 의 middleware. 응답이 아니라 요청 헤더라야 headers() 가 읽는다

userTimezone = cache (fromMaybe "UTC" . lookup "x-user-timezone" <$> headers)   -- 15 부터 async

-- 클라이언트: 실제 시간대를 쿠키에 (1년)
useEffect (setCookie "user-timezone" (resolvedTimeZone intl) { path = "/", maxAge = 31536000 }) []
-- 첫 방문은 IP 추정, 그 뒤는 정확. 서버가 맞게 그려서 FOUT 없음

-- 대안: useSyncExternalStore — getServerSnapshot = "UTC", getSnapshot = 실제
--   서버 렌더·하이드레이션에만 서버 값을 쓰고 다시 그린다: 하이드레이션 에러는 없지만 FOUT
```
