![① 깨진 값 해독: decodeURIComponent 를 한 번 돌려도 %20 이 남으면 이중 인코딩이고, 한글은 풀리니 공백만 다시 인코딩됐다. ② 경로 좁히기: 액세스 로그의 %2520 요청이 iOS 에 몰리고 Referer 가 비어 있으면 복사-붙여넣기 경로다. ③ 우리 코드 배제: 링크 생성이 인코딩을 한 번만 하면 원인은 밖이고, iOS 버전으로 좁혀 WebKit Bug 261936 을 찾는다. ④ 고칠 수 없으니 막는다: 화이트리스트 라우트에서만 한 번 더 디코딩, 디코딩 뒤 .. // \ 차단, segment 별 재인코딩 후 301. 무조건 이중 디코딩은 ..%252f 를 ../ 로 만들어 path traversal 이 된다. ⑤ 방어 확인: curl -I 로 %2520 URL 은 301 로 정상 경로, ..%252f URL 은 차단되는지 본다.](/svg/url_2520_debug_flow.svg)

```haskell
-- URL 의 공백이 %2520 으로 깨져 들어온다 = iOS 17.0·17.1 pasteboard 가 복사할 때 다시 인코딩 (WebKit 261936)
-- 인코딩은 멱등이 아니다
encode "%20" == "%2520"          -- % 가 %25 로
decode "%2520" == "%20"          -- 한 번 풀어도 %20 이 남으면 이중 인코딩

pasteboard :: IOS -> String -> String
pasteboard v | v `elem` [17.0, 17.1] = encodeInvalid   -- %20 을 invalid 로 보고 % 를 다시 인코딩. 한글(%EA%B0%80)은 유효해서 통과
             | v < 17                = id              -- NSURL URLWithString: 이 nil
             | otherwise             = id              -- 17.2 수정

-- 추적: 깨진 값 해독 → 경로 좁히기 → 우리 코드 배제
cause :: Request -> Cause
cause r | iOS (ua r) && isNothing (referer r) = Paste   -- 클릭(JS redirect)은 pasteboard 를 안 거쳐 정상
        | otherwise                            = Ours    -- 링크 생성의 encodeURIComponent 가 한 번인지 본다

-- 고칠 수 없으니 막는다
redirect :: Path -> Response
redirect p | not (whitelisted p)                   = pass p
           | any (`isInfixOf` d) ["..", "//", "\\"] = Forbidden
           | otherwise                             = Moved301 (encodeSegments d)
  where d = decode p
-- 무조건 이중 디코딩 금지: decode (decode "..%252f") == "../" — path traversal

-- 확인: curl -I
redirect "/a%2520b"         == Moved301 "/a%20b"
redirect "/..%252f..%252f" == Forbidden

-- URL 은 디코딩된 원본으로 보관하고, 인코딩은 출력 직전 한 번
-- "방어적으로 한 번 더" 는 멱등이 아닌 연산엔 통하지 않는다
```
