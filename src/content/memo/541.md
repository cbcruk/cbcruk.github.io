시뮬레이터 Safari를 GUI로 디버깅할 땐 inspect-webkit(CDP 브리지)이 아니라 **macOS Safari 개발자용 메뉴**가 정도. inspect-webkit은 AI agents/CI용 (README 명시).

## 현상

inspect-webkit이 안내한 Chrome / VS Code / Safari 세 경로 중 Chrome·VS Code(+호스팅 DevTools)를 시도 → GUI 디버깅은 전부 막힘.

## 원인

- **Chrome (`chrome://inspect`)**: 디스커버리 자동 아님 → `localhost:9222` 수동 등록 필요. 등록 후에도 안 뜸 (Chrome 측 고착)
- **VS Code attach** (`type: chrome, port: 9222`): attach는 되지만 **JS 디버거뿐, Elements/Styles 패널 없음** → 웹 UI 디버깅엔 무의미
- **호스팅 DevTools** (`chrome-devtools-frontend.appspot.com`): revision hash가 Chrome 버전마다 달라 임의 URL은 **404**
- 근본: inspect-webkit은 README부터 "AI agents and CI" 타겟 — 사람 GUI 디버깅은 주력 시나리오 아님

`curl localhost:9222/json/list`가 시뮬레이터 탭을 정상 반환 → **iOS↔브리지는 정상, 문제는 Chrome/소비 측**으로 범위 확정.

## 해결

- GUI 디버깅: **macOS Safari 개발자용 메뉴** (번역 레이어 없는 풀 기능)
- 스크립트 주입형이면: **Eruda** (브리지 레이어 불필요, WIR response-body 한계도 무관)

## 교훈

- 도구의 *의도된 사용자*를 먼저 읽는다 (README "for AI agents and CI")
- 레이어 분리 진단: `/json/list` 한 번이 iOS 측 / Chrome 측을 갈라준다
