![노드마다 child(첫 자식), sibling(다음 형제), return(부모) 세 링크가 걸려 있다. App 의 child 는 Header, Header 의 sibling 은 Main, Main 의 child 는 List, 각자의 return 은 부모다. 규칙은 넷: child 가 있으면 내려가고, root 에 도달하면 끝내고, sibling 이 없으면 return 으로 올라가며 반복하고, sibling 이 있으면 옆으로 간다. 내려가는 길이 beginWork, 올라오는 길이 completeWork 라 한 노드를 두 번 지난다. 순서: begin App → begin Header → complete Header → begin Main → begin List → complete List → complete Main → complete App.](/svg/fiber_pointer_traversal.svg)

```haskell
-- Fiber 가 렌더링을 쪼갤 수 있는 이유: 진행 상태가 콜 스택이 아니라 포인터 하나다
data Fiber = Fiber { child, sibling, return :: Maybe Fiber }

-- 재귀: 어디까지 했는지가 콜 스택 프레임(App → Main → List)에 있다
-- 양보하려고 빠져나오면 프레임이 풀려나가고, 스택 위 모두가 중단을 알아야 한다
walk f = beginWork f >> mapM_ walk (children f) >> completeWork f

-- 세 포인터: 한 걸음 = 다음 workInProgress. 멈추면 이 값 하나만 남고, 거기서 다시 시작한다
next :: Fiber -> Maybe Fiber
next f = child f <|> up f                                  -- 내려간다 (beginWork)

up :: Fiber -> Maybe Fiber
up f | isRoot f  = Nothing                                 -- 끝
     | otherwise = sibling f <|> (return f >>= up)         -- 옆으로, 없으면 올라간다 (completeWork)

-- App{Header, Main{List}}: 한 노드를 두 번 지난다
-- begin App → begin Header → complete Header → begin Main → begin List
--   → complete List → complete Main → complete App
-- 원문도 Fiber 사정이라 못박는다 — "apply to Fiber, but not necessarily anything else"
```
