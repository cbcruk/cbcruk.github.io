**조기 종료를 `take`에 위임하면 필요한 만큼만 fetch 한다 — `take`가 끝나면 `return()`이 체인을 거슬러 소스까지 닫는다.**

페이지네이션 API에서 "조건에 맞는 N개"만 필요할 때 꺼낸다. sync 는 이미 네이티브(`iter.filter(f).take(n)`, 모던 브라우저·Node 22+)고, async 쪽은 Async Iterator Helpers 제안(Stage 2)이라 core-js 폴리필로 쓴다.

```ts
import 'core-js/proposals/async-iterator-helpers.js'

type Page<T> = { items: T[]; next: string | null }

/** 커서 페이지네이션 API 를 순회한다 — 현재 페이지를 다 당긴 뒤에야 다음 페이지를 받는다. */
async function* fetchPages<T>(url: string | null): AsyncGenerator<T> {
  while (url) {
    const { items, next }: Page<T> = await fetch(url).then((r) => r.json())
    yield* items
    url = next
  }
}

await AsyncIterator.from(fetchPages<Item>('/api/items')).filter(isValid).take(10).toArray()
```

`fetchPages` 에 요청 수를 세어 두고 10개가 첫 몇 페이지에서 채워질 때 그 이상 요청이 안 나가면 된 것이다. 소스에 `try/finally` 를 두면 `take` 가 끝날 때 `finally` 가 도는 것도 보인다 — 연결·커서 정리는 거기 둔다.

다만 **제안이 아직 개정 중이다** — `next()` 를 await 없이 여러 번 부르면 `map`·`filter` 가 동시에 도는 방향인데 정해지지 않아서, 폴리필과 최종 동작이 다를 수 있다. 순차로 당기는 지금 쓰임새(`toArray`)엔 영향이 없다. 그리고 **TS 타입이 없다** — TS 5.8 lib 에도 core-js 에도 `AsyncIterator.from` 선언이 없어 직접 선언해야 한다.

폴리필 없이도 닫힘 자체는 `for await` 에서 `break` 하면 똑같이 일어난다 — 체이닝이 없을 뿐이다.
